# Module mapping

This map describes the implementation after the profile, structured diet-plan, meal-record, progress-history, appointment, and Admin settings updates. "Partial" means the page/API exists but does not yet meet the end-to-end requirement; page existence alone is not counted as working behavior.

## Registration, routes, and persistence notes

- React route declarations and frontend role gates are in `Diet_Nutrition_Frontend/src/App.jsx`; the backend independently authorizes API roles in `Diet_Nutrition_Backend/src/main/java/com/example/ApiAuthorizationInterceptor.java`.
- Signup, email OTP verification, login, password reset, and Admin login are handled under `/api/auth` by `AuthController`. Public signup accepts patient and nutritionist roles only; Admin accounts use the separate Admin login and must be provisioned by a trusted operator.
- Verified login accounts are stored in `accounts`; their password hashes are not returned by Admin APIs or auth responses. The separate legacy `patients`, `nutritionists`, and `managed_users` tables are not the source of truth for registered-account management or the patient/nutritionist/user overview counts.
- Normal application configuration targets MySQL database `diet_nutrition`; test configuration uses H2 only. A passing H2 test suite does not verify the machine's MySQL connection. New nullable profile and diet-plan fields, `nutritionist_availability`, `meal_records`, and `appointments` are managed by the existing Hibernate `ddl-auto: update` setting when the application starts against MySQL; back up real data before a first production-like schema update.
- MySQL Workbench is a client for viewing tables, not a database server. Connect it to an already-running MySQL instance using that instance's own host, port, database, and credentials; no database credentials or live MySQL rows were tested as part of these code changes.
- Patient assignment is stored in `nutrition_patients`. Nutritionist reads and writes check this relationship. Admin Reports can view the selected patient's saved report sections; this does not grant Admin access to Nutritionist-only patient-management endpoints.
- JPA entities in `Diet_Nutrition_Backend/src/main/java/com/example` define the listed tables. Several patient-facing and nutritionist-facing records currently use parallel legacy/current tables; cleaning these up and adding dates are outstanding data-model work.
- Backend tests use an isolated test database. Account status is persisted in `accounts.enabled`; the configured JPA schema update should add the column to an existing database, but live MySQL migration/integration has not been exercised.
